## 1. 产品定位（一句话）

**通用行程规划工具**——帮助有出行需求的个人/家庭创建、编辑、管理旅行行程；Web 端与微信小程序双端共用同一后端与账号体系，数据互通（Web 端规划、小程序查看/轻量编辑）。

小程序在产品中的角色：PRD 发布路线图的 **Phase 2**（F12 多端数据互通），核心价值闭环是「Web 规划、手机查看、一键导航」。

## 2. 账号与多端互通

- 账号体系：**手机号 + 密码**（注册/登录均为此方式；后端短信验证码 sendCode 已删除，PRD 中「手机号+验证码登录」「微信扫码登录」不在当前实现范围）。
- 同一账号 Web 端与小程序数据完全互通：登录同一手机号即看到相同行程数据。
- 认证方式：JWT Bearer Token（详见 [API.md](./API.md) 认证流程）。

## 3. 功能范围（五个页面 + 详情子页）

### 3.1 登录页 `pages/login/index`

**用户故事**: 作为用户，我用手机号+密码登录，以便在手机上访问我的行程。

**验收标准**:
- [x] 手机号输入：+86 前缀、11 位、以 1 开头，格式实时校验，不合规则边框变红
- [x] 密码输入（password 型 input）
- [x] 未勾选《用户协议》《隐私政策》时点击登录 → checkbox 抖动 + toast 提示
- [x] 登录成功 → `uni.switchTab` 进入行程列表（tabBar 页）
- [x] 登录失败 → 密码框与按钮之间显示红色错误文字（如「手机号或密码错误」）
- [x] 提供跳转注册页入口（`navigateTo /pages/register/index`）

### 3.2 注册页 `pages/register/index`

**用户故事**: 作为新用户，我注册一个账号，以便开始规划行程。

**验收标准**:
- [x] 字段：昵称（选填，不填时默认用手机号）、手机号、密码、确认密码
- [x] 两次密码不一致时给出提示
- [x] 注册成功自动登录（后端直接返回 token）并 `switchTab` 进入行程列表
- [x] 同样有协议勾选（未勾选拒绝提交）
- [x] 提供「返回登录」入口（navigateBack）

### 3.3 行程列表页 `pages/trips/index`（tabBar[0]，首页）

**用户故事**: 作为用户，我打开小程序就能看到我所有的行程（含 Web 端创建的），下拉刷新拿最新数据。

**验收标准**:
- [x] 顶部统计条：行程总数 / 累计天数（前端由列表数据计算）
- [x] 行程卡片：封面渐变（coverColor）、目的地胶囊、标题、日期范围、主题/出行方式/人数标签、天数
- [x] 下拉刷新（`onPullDownRefresh`）重新拉取列表
- [x] 每次页面 onShow 都重新拉取（保证 Web 端改动及时可见）
- [x] 左滑卡片露出删除按钮 → `uni.showModal` 二次确认 → 删除后刷新（后端为软删除）
- [x] 点击卡片 → `navigateTo` 行程详情
- [x] 悬浮「+」按钮创建行程（当前实现为页内弹窗简表单：标题/目的地/起止日期；完整表单在 `pages/trips/create` 页）
- [x] 空状态引导（无行程时显示引导文案）
- [x] 加载中状态

**明确不做（MVP）**: 搜索栏、目的地筛选下拉（行程量小，PRD F08 的筛选能力由后端 `sort/destination` 参数预留，前端暂未暴露 UI）。

### 3.4 创建行程页 `pages/trips/create`

**用户故事**: 作为用户，我填写行程基本信息，创建后直接进入详情页开始编排。

**验收标准**:
- [x] 必填：标题、目的地、出发日期、返回日期（date picker，返回日期不早于出发日期，联动调整）
- [x] 选填：出行主题（含快选标签：自由行/亲子游/蜜月/商务/朋友聚会/周末短途）、同行人数（stepper，最小 1）、出行方式（picker：飞机/高铁/自驾/大巴/轮船/其他）、封面色（6 色圆点）
- [x] 提交前逐项校验，缺项 toast 提示
- [x] 创建成功 → `uni.redirectTo('/pages/trips/detail?id=xxx')`（redirectTo 替换当前页，返回不回到表单）
- [x] 提交中按钮禁用并显示「创建中...」

> ⚠️ 已知问题: create.vue 与列表页弹窗创建实际跳转的是短路径 `pages/trips/detail`，而 pages.json 注册路径为 `pages/trips/detail/index`，真机运行时该跳转会失败（页面不存在）；列表页 `goDetail` 用的是完整注册路径，正常。

### 3.5 行程详情页 `pages/trips/detail/index`（核心页面，非 tabBar）

**用户故事**: 作为用户，我按天查看/编排行程条目，需要时切到地图看位置分布，把 Web 端规划的行程在手机上落地执行。

**验收标准**:
- [x] 顶部：返回按钮 + 行程标题 + 目的地/日期摘要
- [x] 日期横滑 Tab（Day N + 日期），切换查看对应天
- [x] 列表/地图双视图 Segmented Control 切换，默认列表
- [x] 列表视图：条目卡片（类型色点、名称、时间、地址、备注）；非排序态下卡片右侧有「编辑/删除」按钮
- [x] 排序模式：工具栏「排序」按钮进入，每个条目 ↑/↓ 按钮（到顶/到底禁用），每次点击立即调 reorder API（乐观更新，失败回滚重拉）
- [x] 删除条目：`uni.showModal` 确认后硬删除
- [x] 添加条目：底部「添加条目」按钮 → 底部弹出表单（Bottom Sheet）：POI 搜索（关键词 → 后端高德代理 → 结果列表 → 选中回填名称/地址/坐标/poiId）+ 手动表单（类型五选一/名称/地址/时间 picker/备注）
- [x] 编辑条目：底部弹出表单，字段预填，保存后本地更新
- [x] 地图视图：小程序原生 `<map>`，markers 取当天有坐标条目（callout 常显名称），虚线 polyline 串联顺序，无坐标时中心默认（当前实现：取第一个有坐标条目，兜底北京）
- [x] 加载失败错误态（「行程不存在或无访问权限」）

**与 UI 规范的差异（当前实现）**: 未做「编辑行程信息」「分享行程」的 ActionSheet 入口、marker 点击信息条与导航按钮、`onShareAppMessage` 分享——见 §5 后续规划。

### 3.6 发现页 `pages/discover/index`（tabBar[1]）

- MVP 占位页：「发现功能开发中」。对应 PRD P2（模板库/推荐）预留。

### 3.7 我的页 `pages/mine/index`（tabBar[2]）

**验收标准**:
- [x] 已登录：头像占位（昵称首字母）、昵称、脱敏手机号（138****1234）
- [x] 行程统计：全部行程 / 即将出发 / 已完成（前端按日期计算）
- [x] 菜单：我的行程（switchTab）/ 收藏夹、设置（占位 toast「功能开发中」）/ 关于（版本弹窗）/ 退出登录（showModal 确认 → 清 token → reLaunch 登录页）
- [x] 未登录：占位头像 + 「去登录」按钮

## 4. 明确不做的（与 Web 端差异）

以下 Web 端能力小程序端**有意裁剪**（来源: PRD + MINI-PROGRAM-UI-SPEC.md §11「不做的事」）:

| 裁剪项 | 原因 | 回归条件 |
|---|---|---|
| 行程搜索 / 目的地筛选 UI | 手机端行程数量少（个位数），无需搜索 | 行程数 > 20 |
| 条目长按拖拽排序 | 小程序 movable-area 实现复杂、手感差 | 用户反馈 ↑/↓ 排序效率低时改拖拽 |
| 登录页 CSS 动画角色 | 手机端性能差且分心 | — |
| 创建行程底部弹出 | 字段多，独立页面体验更好（已在 create 页落地） | — |
| 上拉分页加载 | 行程数据量小，一次拉完 | — |
| 地图拖拽分隔线 / 三栏布局 | 375px 宽度放不下，改为列表/地图双视图切换 | — |
| 未登录浏览公开分享行程 | 分享功能未上线 | 分享上线时 |
| 实时协同编辑 | PRD 3.3 明确不做（单人规划为主场景） | — |
| 社区/UGC、订单交易、多语言 | PRD 3.3 明确 MVP 不做 | — |

PRD 功能对照: 小程序 MVP 覆盖 F01(注册/登录)、F02(创建行程)、F03(按天编排)、F04(条目管理+删除二次确认)、F05(排序，降级为 ↑/↓ 按钮方案)、F06(POI 搜索)、F07(地图展示)、F08(行程列表/详情)、F12(多端互通)；**F09 路线规划、F10 行程分享、F20 导航跳转、F11 备注/清单（独立功能）不在当前 MVP**，见 §5。

## 5. 版本边界：当前 MVP vs 后续规划

### 当前 MVP（已完成，全链路验证通过）

## 6. 非功能需求

- **域名白名单**: 微信公众平台需配置 request 合法域名 `https://qinzilv.cn`（HTTPS），否则真机请求被拦截。本地调试可在微信开发者工具勾选「不校验合法域名」。
- **HTTPS**: 生产后端全链路 HTTPS（qinzilv.cn）。
- **账号互通**: 与 Web 端共享同一账号体系与数据库（手机号+密码，无独立小程序账号）。
- **权限声明**: manifest 已声明 `scope.userLocation`（地图/导航用途）。
- **性能**: 行程量小，列表一次性拉取不分页；地图仅渲染当天条目 markers。
- **数据隐私**: 行程数据私有；手机号脱敏展示；遵守《个人信息保护法》。
